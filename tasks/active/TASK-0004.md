## Goal

Produce a versioned, deterministic, offline-regenerable GeoNames/IANA catalog of exactly 400 major or widely recognized cities, with source provenance, explicit curation inputs, validation, drift detection, and attribution in the repository and distributed static artifact.

## Non-goals

- No city picker/search UI, add/remove world clocks, persistence or `localStorage`, clock-card/dashboard redesign, settings, or alarms.
- No runtime GeoNames/IANA API request, GitHub Actions/deployment change, or new production dependency.
- Do not introduce an npm dependency merely for parsing/generation without escalation and reassessment.

## Context

TASK-0003 established framework-independent time formatting with native `Date`/`Intl`. The implementation plan places the catalog before world-clock management and persistence in TASK-0005. The application is a static SPA whose city catalog must be bundled; source-data acquisition and regeneration are development-time concerns.

## Approved source and curation contract

- Use the official GeoNames `cities15000.zip` as the upstream candidate dataset. Acquire an identifiable snapshot, then commit an extracted/normalized generator input suitable for deterministic offline regeneration. Ordinary build/test/CI must never request GeoNames or implicitly use its latest contents.
- Record the authoritative upstream URL, actual retrieval/snapshot metadata available at acquisition, SHA-256 of the acquired ZIP, SHA-256 of the committed generator input, and applicable GeoNames attribution/license. Do not invent dates, hashes, or metadata before acquiring the bytes. Preserve attribution in repository documentation and the distributed static artifact.
- Parse and validate the pinned candidate snapshot. Version `manualInclude` and `manualExclude` as explicit GeoNames `geonameId` inputs. They must be disjoint, every referenced ID must exist in the pinned source, and invalid curation input must fail generation.
- Every valid `PPLC` record is mandatory and cannot be manually excluded. Start with all mandatory `PPLC` records and all manual includes. Fail if that set exceeds 400.
- Fill remaining slots from eligible unselected records by population descending and then `geonameId` ascending. Automatic filling is capped at 10 selected cities per `countryCode`, counting capitals and manual includes. Mandatory/manual selections may exceed 10 for a country; add no further automatic entries from that country in that case.
- Stop at exactly 400 entries; fail if the validated source and rules cannot yield exactly 400. Serialize runtime output in deterministic, locale-independent `geonameId` ascending order unless implementation evidence establishes a simpler equally deterministic representation.

## Escalation triggers

- If actual GeoNames format/licensing materially conflicts with this source contract, or an identifiable snapshot requires an architecture change or runtime network dependence: stop, record evidence, and hand off for architecture/product reassessment.
- If the approved rules cannot deterministically yield exactly 400 valid entries, or significant additional source datasets are required: stop and hand off for a human curation/source decision.
- If a consequential new dependency or TASK-0005 functionality is needed: stop and reassess scope and routing before implementation.
- If deterministic offline verification cannot be produced without weakening a gate: record the limitation and escalate under `docs/AI_WORKFLOW.md`.

## Acceptance criteria

- [ ] The committed source input and explicit curation inputs regenerate a byte-identical catalog offline. Provenance records the authoritative URL, actual acquisition metadata, ZIP and committed-input SHA-256 values, and applicable attribution/license; no unobserved metadata is asserted.
- [ ] The generated runtime catalog has exactly 400 unique `geonameId` values and includes `geonameId`, `name`, `asciiName`, `countryCode`, and `timeZone` for every entry. Names are non-empty; `countryCode` is a valid two-letter code; each explicit `timeZone` is accepted by the approved native `Intl.DateTimeFormat` environment.
- [ ] Generation fails with useful diagnostics for malformed source records, invalid or overlapping curation IDs, exclusion of a mandatory `PPLC`, an oversized mandatory set, an insufficient eligible pool, or invalid time zones. It never silently repairs or invents time zones.
- [ ] Selection follows the approved mandatory, population, ID tie-break, and per-country cap rules. Tests cover these rules and deterministic ordering with small controlled inputs.
- [ ] Generated strings are serialized structurally/safely rather than interpolated as executable source text. Generation and validation are framework-independent; the generated catalog is never hand-edited.
- [ ] The generated catalog is committed, deterministic, validated, framework-independent, and immediately consumable by TASK-0005. Normal build/test/CI and catalog regeneration checks run without a GeoNames network request. `make test-integration` validates regeneration and fails when the committed generated output drifts. The production build includes attribution as a static artifact; TASK-0004 does not modify application runtime/UI merely to place the catalog in `dist/`.
- [ ] No new production dependency, runtime external lookup, deployment change, or TASK-0005 behavior is introduced.
