## Goal

Add one global clock presentation preference (digital or analog) and one global digital time-format preference (24-hour or 12-hour), apply them consistently to the local clock and all selected world clocks, and persist them without losing existing TASK-0005/TASK-0010 city selections.

## Non-goals

- No alarm domain or runtime behavior from TASK-0007/TASK-0008.
- No city-catalog changes, picker redesign, reordering, backend/runtime API, router/store/UI framework, or new production dependency.
- No final visual/release acceptance work from TASK-0009.
- Do not change the existing one-second shared `currentInstant` ticker architecture.
- Do not resolve or weaken `LEARN-20260925-155537` as part of this task.

## Context

TASK-0010 is integrated into `main`, hosted CI passed, and the product owner manually accepted the searchable city combobox. The current UI is digital-only and the persisted configuration schema is exact version 1 with only `selectedCityIds`. FR-005 and FR-006 require global digital/analog and 12h/24h settings with persistence. ADR-001 requires the same small Vue/TypeScript/plain-CSS architecture and typed versioned `localStorage` adapter.

Current product behavior is the backward-compatible default:
- presentation mode: `digital`;
- digital time format: `24h`.

## Configuration migration contract

- Introduce a new exact current configuration schema version that stores:
  - ordered unique `selectedCityIds`;
  - global presentation mode `digital | analog`;
  - global digital time format `24h | 12h`.
- The preferred shape is version 2, preserving version 1 solely as a supported migration input.
- A valid version-1 document must load as the version-2 in-memory configuration with all selected city IDs preserved and the new defaults `digital` + `24h`.
- Migration must not require an eager storage write merely from loading. The migrated current-version document may be persisted on the next normal user change.
- A valid current-version document must restore all three configuration fields exactly.
- Malformed current-version documents must recover to safe current-version defaults using the established invalid-data behavior.
- A future/unsupported version must retain the established safe-default/non-overwrite behavior: show usable defaults in the tab, surface the unsupported-version warning, and do not overwrite the stored future document when the user changes cities or presentation settings.
- Storage read/write failure behavior must remain graceful and visible as today.
- Exact validation must reject unknown extra fields, invalid enum values, invalid/duplicate/non-catalog city IDs, and wrong field types.

## Presentation contract

- Provide visible, accessible global controls for:
  - presentation mode: Digital / Analog;
  - digital time format: 24-hour / 12-hour.
- Controls apply to the local clock and every world-clock card, not per-clock.
- Digital mode:
  - `24h` preserves the current 24-hour display semantics;
  - `12h` uses correct civil time for the same local/IANA zone and visibly distinguishes AM/PM.
- Analog mode:
  - render a real analog representation with hour, minute, and second hands derived from each clock's civil time;
  - local and world clocks must use the same shared `currentInstant`; do not create per-clock timers;
  - hand positions must reflect the applicable local/IANA zone, including representative offset/DST cases;
  - the 12h/24h preference remains persisted but does not alter analog hand positions; when returning to digital mode, the chosen digital format takes effect.
- Analog clocks must retain an accessible textual representation of the current civil time so assistive technology is not forced to infer hand positions.
- Keep city name, zone identity, removal controls, storage warnings, and searchable-combobox behavior intact.
- Styling should be coherent with the existing dashboard and sufficient for functional visual review, while final polish remains TASK-0009.

## Escalation triggers

- If a new production/UI/time-zone dependency appears necessary, stop and reassess instead of adding it.
- If the persistence change cannot preserve valid V1 selected-city data deterministically, stop and record the migration issue before editing broader UI.
- If implementing analog time requires abandoning native `Intl`/IANA semantics, adding per-clock timers, or changing the catalog, stop and reassess.
- If the change requires alarm semantics, deployment/workflow changes, or a broader design-system decision, stop and hand off for replanning.
- Do not silently alter the existing Playwright timing assertion or either current learning candidate.

## Acceptance criteria

- [ ] Visible global controls allow the user to choose Digital/Analog and 24-hour/12-hour through browser UI.
- [ ] Defaults preserve current behavior: Digital + 24-hour.
- [ ] Changing presentation mode updates the local clock and all selected world clocks consistently.
- [ ] Changing 24h/12h format updates all digital clocks consistently; 12h visibly distinguishes AM/PM.
- [ ] Analog local/world clocks show hour/minute/second hands corresponding to the same actual instant in each applicable civil time zone and retain accessible textual time.
- [ ] Both settings persist across reloads together with selected cities.
- [ ] Valid V1 stored documents migrate in memory without losing selected-city order and use Digital + 24-hour defaults.
- [ ] Valid current-version documents round-trip exactly; malformed current-version documents recover safely; future/unsupported versions remain protected from overwrite.
- [ ] Storage unavailable/write-failure scenarios leave the current tab usable and surface the established warning behavior.
- [ ] City add/remove/order, searchable combobox behavior, explicit IANA handling, and the single shared ticker remain intact.
- [ ] No alarm behavior, production dependency, catalog change, deployment change, or unrelated visual redesign is introduced.
