## Goal

Replace the bootstrap shell's placeholder status with a running, first-launch clock showing the browser user's current local time, backed by deterministic framework-independent time-formatting/domain primitives. Include seconds so running behavior is observable.

## Non-goals

- Do not implement the city catalog, city selection, additional world clocks, or world-clock management (TASK-0004/0005).
- Do not implement local persistence or configuration recovery (TASK-0005/0006).
- Do not implement digital/analog mode or the user-selectable 12/24-hour setting (TASK-0006). This task does not establish a permanent product default for 12h versus 24h; any interim display format is only a rendering choice for the local clock.
- Do not implement alarm scheduling, evaluation, UI, or audio (TASK-0007/0008).
- Do not redesign deployment, add a date/time library or polyfill, or add a production dependency.

## Context

TASK-0001 supplied a minimal Vue shell and a Playwright Chromium smoke test against the production build at `/MiniJSClock/`. TASK-0002 supplied the CI/manual Pages delivery path and is integrated into `main`. ## Acceptance criteria

- [x] On first launch without configuration, the application visibly shows a running clock with seconds for the browser user's current local time. The local view derives its time zone from the browser; it does not pin a city or IANA zone.
- [x] One current-time source/ticker supplies clock updates and reads actual current time on every execution. It does not derive the next instant by adding a fixed interval to the previous instant, and lifecycle cleanup prevents an orphaned ticker.
- [x] Pure, framework-independent TypeScript time primitives format a supplied instant for an explicitly requested valid IANA time zone using native `Date`/`Intl`. The browser-local view uses the local zone when no explicit time zone is requested.
- [x] An explicitly supplied invalid IANA time-zone identifier produces a clear failure/result and never silently falls back to the browser-local zone.
- [x] Deterministic domain tests use fixed instants and explicit time zones/formatting inputs. They cover representative zones and offset/DST behavior, including instants on both sides of at least one DST transition. Tests do not rely on the test runner's wall-clock time or local time zone for expected values.
- [x] The local-clock UI does not expose or persist a 12/24-hour preference and does not claim an interim format as the product default.
- [x] Browser smoke coverage loads the production build under `/MiniJSClock/`, verifies first-launch local-clock visibility, and observes running behavior. The assertion checks the browser's local time rather than assuming the CI host's time zone.
- [x] The change adds no production dependency and keeps catalog, persistence, world-clock, mode, and alarm behavior out of scope.
