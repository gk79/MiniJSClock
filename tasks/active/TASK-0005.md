## Goal

Add a visible catalog-backed world-clock selection and removal flow. Persist selected city clocks in one validated, versioned browser-local configuration document, and recover safely when storage is absent, malformed, unsupported, or unavailable.

## Non-goals

- No digital/analog setting, user-selectable 12/24-hour format, alarms, or reordering UI.
- No catalog regeneration or curation change; no persistence of catalog records.
- No backend, runtime external city lookup, Pinia, router, UI framework, or new production dependency.
- No final dashboard redesign or visual-acceptance milestone; no TASK-0006 or later behavior.

## Approved persistence contract

```ts
type ConfigV1 = {
  version: 1
  selectedCityIds: number[]
}
```

- Store the single document under the stable key `minijsclock.config`. Do not store the catalog or browser-local clock in `selectedCityIds`.
- An absent key / first launch yields `{ version: 1, selectedCityIds: [] }`. Zero selected world clocks is valid.
- Each ID is a GeoNames `geonameId` in the committed catalog. IDs are unique. Array order is display order and must survive reload; adding an already selected city must not duplicate it.
- Parsing/validation must reject malformed JSON, invalid document shape, duplicate IDs, and IDs absent from the current catalog. Recover to an empty selection without a crash and show a visible non-blocking recovery indication.
- An unsupported `version` is not a valid `ConfigV1`: use safe in-memory defaults and show a visible non-blocking warning.
- Web Storage read/write exceptions must not crash the app. Selection/removal must remain usable in-session, with a visible non-blocking indication when persistence is unavailable or a write fails.
- Keep validation, load, and save independently unit-testable against a Storage-compatible interface. Vue owns reactive orchestration and UI, not validation semantics.

## User-visible flow and clock semantics

- Preserve the always-present, running browser-local clock on first launch and after recovery.
- Provide a visible search/picker sourced only from the bundled 400-city catalog. Case-insensitive search matches `name`, `asciiName`, and `countryCode`.
- Selecting a catalog city adds one world-clock card. Each card identifies city and country code, shows a running time in that entry's explicit IANA zone, and has a visible removal control.
- Add/remove updates the current view and browser-local configuration. Reload in the same browser profile restores selected cities in the same order; removal remains removed after reload.
- Use one actual-current-time source/ticker for all clocks. Format city times with existing native `Date`/`Intl` logic and each catalog entry's `timeZone`; do not create an interval per card.
- Render catalog/configuration text through normal Vue text bindings, without raw HTML or code execution.

## Acceptance criteria

- [ ] First launch shows the running browser-local clock and no forced world clocks. The city picker uses the bundled catalog only; name, ASCII name, and country-code search are case-insensitive.
- [ ] A user can add two catalog cities; each card shows city and country code and a running time correct for its explicit catalog IANA zone. Duplicate add cannot create duplicate clocks.
- [ ] Removing a city updates UI and stored selection. Add → reload → remove → reload restores the expected cities in the same display order.
- [ ] The stored value uses key `minijsclock.config`, has `version: 1` and only `selectedCityIds`, excludes catalog and local clock, and validates unique IDs against the bundled catalog.
- [ ] Absent storage starts with an empty selection. Malformed JSON, invalid shape, duplicate IDs, unknown IDs, and unsupported versions never crash; invalid/unsupported data yields safe in-memory defaults and a visible non-blocking recovery/warning state.
- [ ] Storage read/write failures leave add/remove usable for the session and visibly report unavailable or failed persistence.
- [ ] One current-time ticker drives local and city clocks; no runtime external lookup, new production dependency, catalog change, or TASK-0006+ scope is introduced.
