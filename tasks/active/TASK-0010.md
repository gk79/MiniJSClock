## Goal

Replace the current separate city-search input plus native select with one modern searchable combobox that filters the bundled city catalog live and adds a selected city without changing persistence, catalog, time-zone, or clock semantics.

## Non-goals

- No TASK-0006 global digital/analog or 12h/24h settings.
- No alarm behavior, reordering, catalog regeneration/curation, persistence-schema changes, backend, runtime city lookup, router/store/UI framework, or new production dependency.
- No broad dashboard redesign or final visual-acceptance work.
- Do not change the existing single-ticker clock architecture or storage recovery semantics.

## Context

TASK-0005 is integrated into `main` and currently renders a separate `<input type="search">` and native `<select>` for city addition. Product-owner manual review requested one combined searchable control: the user types a city-name prefix into the same control that exposes matching selectable cities. Requirements now make that interaction explicit. The existing bundled catalog, selected-city persistence, duplicate exclusion, add/remove behavior, and world-clock rendering remain authoritative.

See `docs/product/requirements.md`, `docs/architecture/decisions/ADR-001-frontend-stack.md`, `docs/quality/quality-strategy.md`, and `docs/delivery/implementation-plan.md`.

## Interaction contract

- Render one visible city-selection combobox rather than a separate search box and select control.
- The same control accepts text input and exposes a live-filtered popup/list of currently unselected bundled cities.
- City-name and ASCII-name matching is case-insensitive and prefix-based after trimming leading/trailing whitespace. Preserve country-code discovery as a secondary case-insensitive match so existing catalog discoverability is not regressed.
- Clicking/tapping a result selects it and adds the city clock.
- Keyboard interaction must support at least:
  - opening/showing matching results by typing or focusing the control;
  - moving through results with ArrowDown/ArrowUp;
  - selecting the active result with Enter;
  - closing the popup with Escape without adding a city.
- After a city is added, the text query should clear and the selected city must no longer appear in available results.
- Duplicate city clocks must remain impossible.
- The control must expose appropriate accessible combobox/listbox semantics and a usable visible label or accessible name. Do not use raw HTML injection.
- Zero-match state must be understandable and must not add a city.
- Existing add/remove persistence and storage-warning behavior must remain unchanged.

## Acceptance criteria

- [x] The separate city-search input and native city select are replaced by one searchable combobox.
- [x] Typing a city-name or ASCII-name prefix filters currently unselected bundled cities live, case-insensitively; country-code discovery still works case-insensitively.
- [x] A user can add a city with both pointer interaction and keyboard Arrow/Enter interaction.
- [x] Escape closes the result popup without adding a city; a zero-match query adds nothing and provides an understandable empty result state.
- [x] Adding a city clears the query, removes that city from available results, and cannot create a duplicate clock.
- [x] Existing selected-city order, reload persistence, removal persistence, storage recovery/warnings, explicit IANA time formatting, and single shared ticker continue to work.
- [x] No production dependency, catalog change, persistence-schema change, runtime network lookup, TASK-0006 behavior, or unrelated redesign is introduced.
